# AI 协作与文档维护规范

## 目标

让后续 AI agent 在 V2 分支中保持上下文干净、读写路径稳定、更新范围可控，避免重新陷入旧项目的历史文档污染和 runtime 伪成功问题。

## 上下文加载原则

AI 不应一次性加载全仓库。默认采用分层读取：

1. 根入口：`README.md`、`AGENTS.md`。
2. 文档入口：`doc/README.md`。
3. 目录入口：相关目录 `INDEX.md`。
4. 任务文档：与任务直接相关的 1 到 3 个文档。
5. Forensic lookup：仅在用户明确要求时读取旧实现或历史审计材料。

## 写作规则

- 使用明确标题和短段落。
- 每个文档开头说明职责和非职责。
- 约束用 MUST / MUST NOT / SHOULD / MAY 或中文等价表达。
- 不用“以后再说”替代验收标准。
- 不把设计判断埋在长叙述里；重要决策写入 `decisions.md`。

## 索引规则

每个目录的 `INDEX.md` 至少包含：

1. 本目录职责；
2. 文件清单；
3. 推荐阅读顺序；
4. 更新触发条件。

新增、删除、重命名文档时，必须同步 `INDEX.md`。

## 防漂移规则

禁止以下行为：

- 为了完成任务读取大量旧文档并引入旧术语。
- 在没有更新 backlog 的情况下新增实现范围。
- 在没有更新 acceptance criteria 的情况下改变验收语义。
- 在没有 decision record 的情况下改变架构方向。
- 把 runtime convenience 当作产品能力。

## 任务结束时更新

一次有效变更通常需要同步：

```text
相关文档
+ 目录 INDEX.md
+ backlog.md
+ decisions.md 或 月度日志
```

小拼写修复可不更新决策日志。

## 文档长度控制

建议单个 Markdown 文件不超过 500 行。超过时应拆分专题文档，并在原文件保留摘要和链接。
