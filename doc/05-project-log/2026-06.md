## 2026-06-01 — V2-090C ServiceRunEvidence

- 工作包：V2-090C（ServiceRunEvidence，服务运行证据）
- 关键产出：新增 `src/boardroom_os/evidence/service_run.py`、`tests/negative/test_service_run_evidence_fail_closed.py`、`tests/negative/test_service_run_closeout_gate.py`、`tests/evidence/test_service_run_evidence.py`、`tests/execution/test_service_runner.py`；同步更新 `src/boardroom_os/adapters/process_runner.py`、`src/boardroom_os/evidence/claim.py`、`src/boardroom_os/evidence/verifier.py`、`src/boardroom_os/closeout/gate.py`、`src/boardroom_os/workspace/evidence_export.py`、`tests/closeout/test_closeout_gate.py`、`tests/proving/test_workspace_evidence_export.py`。
- 关键实现：`ServiceRunEvidence`（服务运行证据）记录 declared `PackageCommand`（包命令）启动后的 process id、readiness URL（就绪 URL）、HTTP probe status/body sha256（HTTP 探针状态/内容哈希）、stdout/stderr refs（标准输出/错误引用）和时区时间；`ServiceRunner`（服务运行器）真实启动子进程并等待 HTTP readiness probe（HTTP 就绪探针）通过后生成服务证据，进程提前退出、错误端口/path、非 UTF-8 输出和时钟回退均 fail closed（失败关闭）。
- Evidence / closeout 接入：`EvidenceClaimSourceKind.SERVICE_RUN`（服务运行来源）和 `build_evidence_claim_from_service_run`（服务运行证据声明构建器）接入 `EvidenceVerifier`（证据验证器）；`required_artifact_type="service_run"` 必须解析到真实 `ServiceRunEvidence`（服务运行证据），且 artifact refs（制品引用）必须等于 canonical service stdout/stderr refs（规范服务标准输出/错误引用）。`CloseoutGate`（收尾门禁）要求 `RUN`（运行命令）绑定 `ServiceRunEvidence`，`TEST`（测试命令）继续绑定 `VerificationRun`（验证运行）；缺 service readiness（服务就绪）时返回 `COMMAND_EVIDENCE_NOT_FINAL`，message（消息）包含 `RUN_MANIFEST_SERVICE_NOT_READY`，`related_ref` 指向 command id（命令编号）。
- Workspace export：`WorkspaceEvidenceBundle`（工作区证据包）新增 `service_run_refs`（服务运行引用）和 artifact kind（制品类型）`SERVICE_RUNS`，固定导出路径 `20-evidence/tests/service-runs.json`，并拒绝 orphan service run（孤儿服务运行证据）。
- Negative tests：证明只有 process id 无 readiness probe、服务启动后立即退出、probe 非 2xx、缺时区时间、`required_artifact_type="service_run"` 却来自 `VerificationRun`（验证运行）、`RUN` command 仅有 `VerificationRun` 或缺 service readiness 时均不可通过。
- Happy path：标准库 HTTP server fixture（HTTP 服务夹具）返回 `/health` 200 后，`ServiceRunner`（服务运行器）记录 readiness URL、probe body sha256、stdout/stderr refs 与时间；`build_evidence_claim_from_service_run`（服务运行声明构建器）产出的 claim（证据声明）可被 `EvidenceVerifier` 验证为 `service_run`；workspace bundle（工作区证据包）保留 `service_run_refs` 并包含 `service-runs.json`。
